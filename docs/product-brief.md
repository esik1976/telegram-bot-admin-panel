# Product Brief. Telegram Bot Admin Panel

## Название продукта

Telegram Bot Admin Panel.

## Проблема

Telegram-боты из предыдущих уроков управляются через код и `.env`: чтобы изменить системный промпт, модель, поведение или посмотреть историю взаимодействий, нужно заходить в файлы, перезапускать приложение и читать логи вручную.

Это неудобно, если бот должен использоваться как реальный продукт: владелец хочет управлять настройками без разработки, видеть активность пользователей и быстро менять сценарии.

## Целевая аудитория

Основной пользователь:

- владелец Telegram-бота;
- администратор учебного или сервисного AI-бота;
- разработчик, который хочет иметь простую панель управления ботом.

Вторичный пользователь:

- оператор поддержки;
- методолог курса;
- менеджер продукта.

## Ценность

Продукт дает web-панель, где можно:

- управлять системным промптом;
- выбирать LLM-модель;
- смотреть историю сообщений;
- видеть ошибки и статусы;
- управлять пользователями;
- включать и выключать функции: текст, голос, изображения, инструменты.

## MVP

В первую версию входит:

- web-админка с авторизацией администратора;
- dashboard со статусом бота;
- управление системным промптом;
- управление настройками моделей;
- просмотр последних диалогов;
- просмотр ошибок;
- базовая таблица пользователей Telegram;
- backend API для админки;
- подключение к существующему Telegram-боту;
- PostgreSQL для хранения настроек, пользователей и сообщений.

## Out of scope

В первую версию не входит:

- сложная ролевая модель;
- биллинг;
- marketplace промптов;
- мультиязычная админка;
- полноценная CRM;
- массовые рассылки;
- ручной ответ оператора из админки;
- аналитика стоимости токенов в реальном времени.

## Ограничения

- Стек должен быть понятным для учебной реализации.
- Проект должен развиваться итерационно.
- Первая версия должна запускаться локально.
- Деплой должен быть возможен на Railway или аналогичной PaaS.
- Секреты не должны храниться в репозитории.
- Для MVP достаточно одного администратора.

## Критерии успеха

- Администратор может войти в web-панель.
- Администратор может изменить системный промпт без редактирования кода.
- Бот использует актуальные настройки из базы данных.
- В панели видны последние сообщения пользователей.
- В панели видны ошибки обработки сообщений.
- Проект имеет понятную архитектуру, roadmap и task decomposition.
